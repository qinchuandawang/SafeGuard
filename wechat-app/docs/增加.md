# 增加.md - AI智能体反诈骗系统增强总结

## 一、RAG 系统（知识库增强检索）

### 1.1 数据源
- 从公安部刑侦局、国家反诈中心官网获取权威知识
- 整合 《2025版防范电信网络诈骗宣传手册》10类高发诈骗类型
- 整合 8大反诈利器、20个防诈关键词、法律法规等
- 文档存放：`backend/src/main/resources/knowledge/anti_fraud_knowledge.txt`

### 1.2 索引构建流程
```
知识文档 → splitByMajorSection(按标题分割)
  → HybridChunker.hybridChunk(混合切块)
    ├── fixedWindowChunk: 固定大小256字符+32重叠
    └── semanticChunk: 基于段落语义的100~512字符窗口
  → EmbeddingService.getEmbedding(BGE嵌入1024维)
  → MilvusService.insert(存入向量数据库)
```

### 1.3 查询检索流程
```
用户查询 → HybridChunker.chunkQuery(混合切块)
  → EmbeddingService.getEmbedding(BGE嵌入)
  → RAGService.matchKeywords(规则过滤→关键词匹配)
  → MilvusService.search(HNSW检索 topK*3)
  → ReRank(向量分×0.6 + 关键词分×0.4)
  → RAGService.semanticDeduplicate(语义去重)
  → limit(topK=5) → formatRagContext(格式化JSON) → LLM
```

### 1.4 涉及文件
| 文件 | 说明 |
|------|------|
| `rag/RAGService.java` | RAG核心服务（构建+检索全流程） |
| `rag/HybridChunker.java` | 混合切块器（固定+语义） |
| `rag/EmbeddingService.java` | BGE嵌入服务（支持回退hash嵌入） |
| `rag/MilvusService.java` | 向量数据库（内存模拟，预留Milvus生产接口） |
| `rag/ChunkResult.java` | 切块结果DTO |
| `config/RAGConfig.java` | RAG配置参数 |
| `dto/RagQueryResult.java` | 检索结果DTO |
| `controller/RAGController.java` | RAG REST API |

### 1.5 API端点
- `GET /api/rag/query?q=xxx` - 知识检索
- `GET /api/rag/stats` - 知识库状态
- `POST /api/rag/reload` - 重载知识库

## 四、多Agent架构

### 4.1 Agent设计
```
AgentOrchestrator (调度器)
├── TEXT_ANALYSIS Agent → 使用CoT+RAG分析文本
├── KNOWLEDGE Agent → 使用RAG检索知识
├── SIMULATION Agent → 使用ReAct模拟诈骗
├── AUDIO_DETECTION Agent → 预留（对接audio-training）
└── VIDEO_DETECTION Agent → 预留（对接video-training）
```

### 4.2 Orchestrator执行流程
```
接收请求 → 保存到短期记忆 → [可选]RAG检索
→ [可选]CoT推理 → [可选]ReAct推理
→ 并行执行多个Agent → 合并结果
→ 生成最终报告 → 保存系统响应到记忆
```

### 4.3 涉及文件
- `agent/AgentOrchestrator.java`

- `dto/OrchestratorRequest.java`

### 4.4 API端点

- `POST /api/agent/analyze/text` - 文本分析（自动使用CoT+ReAct+RAG）
- `POST /api/agent/simulate` - 模拟（自动使用ReAct+RAG）

## 五、记忆系统（短期+长期）

### 5.1 设计
| 特性 | 短期记忆 | 长期记忆 |
|------|----------|----------|
| 存储 | 内存Map | 内存+磁盘持久化 |
| 容量 | 50条/会话 | 1000条/会话 |
| 有效期 | 2小时无活动 | 7天(TTL) |
| 转入条件 | 自动 | 重要性≥0.6自动转入 |
| 淘汰策略 | LRU | 按重要性排序淘汰 |

- 重要性计算公式：基础分0.3 + 长度因子 + 关键信息因子
- 记忆检索：关键词匹配 + 时间衰减
- 定时清理：每5分钟清理过期记忆

## 七、LangChain4j 框架集成

### 7.1 集成架构
```
┌─────────────────────────────────────────────────────┐
│                   LLMService                         │
│  ├── LangChain4j AiService (主路径)                   │
│  │    ├── @SystemMessage + @UserMessage 声明式接口    │
│  │    ├── @Tool 自动调用 (FraudDetectionTools)        │
│  │    └── 自动RAG知识检索                             │
│  ├── LangChain4j StreamingChatLanguageModel (SSE)     │
│  └── 手写 RestTemplate (fallback)                    │
└─────────────────────────────────────────────────────┘
```

### 7.2 依赖配置
```xml
<langchain4j.version>0.26.0</langchain4j.version>

<!-- LangChain4j 核心 -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j</artifactId>
</dependency>
<!-- OpenAI兼容适配器（DeepSeek通过OpenAI兼容API） -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-open-ai</artifactId>
</dependency>
<!-- 嵌入模型 -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-embeddings</artifactId>
</dependency>
<!-- Milvus向量存储 -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-milvus</artifactId>
</dependency>
```

### 7.3 核心组件

| 组件 | 类名 | 说明 |
|------|------|------|
| **ChatLanguageModel** | `LangChain4jConfig.java` | DeepSeek通过OpenAI兼容API，手动配Bean（避免Spring Boot 4.x自动配置兼容问题） |
| **StreamingChatLanguageModel** | `LangChain4jConfig.java` | 流式SSE替代手写174行流式代码，使用TokenStream API |
| **EmbeddingModel** | `LangChain4jConfig.java` | 封装手写EmbeddingService，适配LangChain4j接口 |
| **EmbeddingStore** | `LangChain4jConfig.java` | 封装手写MilvusService（内存模拟），适配LangChain4j接口，可切换MilvusEmbeddingStore |
| **AiService 声明式接口** | `FraudDetectionAiService.java` | 4个AI方法：analyzeText, analyzeMultiModal, scamSimulate |
| **@Tool 工具** | `FraudDetectionTools.java` | 4个工具：searchKnowledge, detectFraudKeywords, getFraudTypeCategories, getAntiFraudHotline |

### 7.4 AiService 声明式接口代码示例
```java
public interface FraudDetectionAiService {
    @SystemMessage("你是一名专业的反诈骗分析专家...可用工具: searchKnowledge...")
    @UserMessage("请分析以下文本: {{text}}")
    String analyzeText(@V("text") String text);
}
```

### 7.5 @Tool 工具代码示例
```java
@Component
public class FraudDetectionTools {
    @Tool("搜索反诈知识库")
    public String searchKnowledge(@P("搜索关键词") String query) {
        return ragService.formatRagContext(ragService.query(query));
    }
}
```

## X、Bug修复记录

### X.1 后端：LangChain4j 0.26.0 API 兼容性修复

**问题**: `EmbeddingSearchRequest`、`EmbeddingSearchResult` 等类在 `dev.langchain4j.store.embedding` 包中不存在

**原因**: LangChain4j 0.26.0（2024年1月发布）API 与后续版本差异较大：
- `EmbeddingSearchRequest`/`EmbeddingSearchResult` 是后续版本新增的类
- `EmbeddingModel.embed(String)` 返回 `Response<Embedding>` 而非 `Embedding`
- `EmbeddingModel.embedAll()` 返回 `Response<List<Embedding>>`
- `EmbeddingStore.addAll(List<Embedding>)` 返回 `List<String>` 而非 `void`
- `EmbeddingStore.findRelevant()` 签名为 `(Embedding, int, double)`
- `StreamingChatLanguageModel` 无 `generate(String)` 便捷方法
- `AiService` 注解处理需要 `langchain4j-spring-boot-starter`

**修复**:
1. `LangChain4jConfig.java` - 使用 0.26.0 原生 API，所有方法签名对齐
2. `LLMService.java` - 移除非流式 ChatLanguageModel 注入（等升级1.x启用）
3. 流式SSE保留手写RestTemplate（已验证稳定）
4. `FraudDetectionAiService`/`FraudDetectionTools` 保留供升级后使用

### X.2 前端：TDesign 版本升级到 1.14.0

**问题**: `tdesign-miniprogram@^0.5.6` 版本在 npm 上已不存在（npm ERR! ETARGET）

**原因**: TDesign 从 0.x 升级到 1.x 后，组件路径从 `tdesign-miniprogram/navbar/navbar` 变为 `tdesign-miniprogram/miniprogram_dist/navbar/navbar`

**修复**:
1. `frontend/package.json` - `^0.5.6` → `^1.14.0`
2. `frontend/app.json` - 所有 `tdesign-miniprogram/` 路径改为 `tdesign-miniprogram/miniprogram_dist/`
3. 创建 `miniprogram_npm/tdesign-miniprogram` 目录链接（junction）指向 `node_modules/tdesign-miniprogram/miniprogram_dist`

### X.3 CodeBuddy 思考模式
- `deepseek-v4-flash` 模型的思考模式为 CodeBuddy 扩展内部设置
- 已在业务层关闭：`application.yml` 中 `llm.enable-thinking: false`
